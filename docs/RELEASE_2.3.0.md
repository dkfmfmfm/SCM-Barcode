# BeyondPack 2.3.0

기준: main 2.2.11. 기존 출고건 현황·라벨 출력·공유 폴더 백업을 유지하면서 작업 이력과 복구를 보강한다.

## 작업 조회·복구

- `이전 작업 조회·이어하기`: 출고건·작업자·작업ID·기간·상태 검색
- 진행 중인 작업 이어하기, 완료된 작업의 박스 조회·재출력·Excel 저장
- 재실행 시 마지막 진행 작업ID와 마지막 라벨 복구
- 정정 중 입력도 작업ID·작업자·정정 대상·사유와 함께 복구
- `현재 작업 완료`와 관리자 도구의 `새 작업 시작` 추가

## 확정 취소·정정

- `선택 박스 확정 취소`: 원본은 취소 이력에 보관하고 실적에서 제외
- 정정 입력 중에는 원본 유지. 정정 확정 시 원본 보관·새 기록 저장·초안 삭제를 한 트랜잭션으로 처리
- 중복 취소, 이미 완료한 작업의 변경, 더 이상 마지막이 아닌 박스의 정정 차단
- 기존 마지막 박스만 정정·취소하는 규칙과 번호 재사용 유지. 적용 후 기존 종이 라벨 폐기 필요
- 취소·정정 이력에서 전체 원본 규격·수량·구성품 조회

## 확정 직전 상품 재검증

- 현재 검증된 로컬 상품DB로 사용중지·미등록·상품정보 변경 검사
- 변경 시 관리자 도구의 `구성품 정보 재확인`으로 실물과 대조 후 재확정
- 검증부터 저장까지 상품 스냅샷 전환을 막아 동기화와의 경합 방지
- 각 박스에 상품DB 버전·검증시각·실제 작업자 기록. 기존 기록에 새 검증시각을 소급해서 부여하지 않음
- 인터넷이 끊긴 경우에도 기존 활성 로컬 DB를 사용. 실시간 Google Sheet 확인을 의미하지 않음

## 자동 백업·복원

- 기본 로컬 포장DB 백업: `data/backups/<PC이름>`
- 선택적 외부 백업과 상품 마스터 Excel 백업 유지
- 최신 DB와 시간별 사본 보관. 보관일수를 적용하되 최신 30개 시간별 사본 유지
- 지난 날짜의 박스를 취소·정정하면 해당 날짜의 CSV도 갱신
- `포장 백업 복원`: 파일 검증 → 현재 기록의 안전 사본 → 전체 기록 복원
- 복원 직전 사본은 `data/backups/before-restore`에 별도 보관하며 자동 정리하지 않음

## 검증

회귀 테스트는 원본 보존, 정정 저장 실패·롤백, 반복 취소, 완료 작업 차단, 버전 변경·사용중지 상품 차단, 동기화 경합, 로컬 백업·복원과 GUI의 재시작·정정 복구를 포함한다. Windows CI에서 Qt 의존성 설치 후 GUI 회귀 테스트와 빌드 EXE 자체검사를 실행한다.

## 운영 범위

로컬 백업은 PC 디스크 고장까지 보호하지 않는다. 외부 백업 위치를 지정해야 한다. 백업 복원은 기존 PC 기록 전체를 교체하며 다중 PC 기록을 병합하지 않는다. 이전 버전에서 이미 삭제된 데이터 중 감사기록에 남지 않은 정보는 복구할 수 없다. 구버전 프로그램으로 다운그레이드하지 않는다.
