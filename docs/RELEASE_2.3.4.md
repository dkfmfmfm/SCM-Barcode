# BeyondPack 2.3.4

현장 문서 세 건을 지금 동작에 맞췄습니다.

**기능 변경은 없습니다.** 2.3.3을 쓰고 있다면 급히 올릴 필요는 없고, 다음 설치 때 함께 반영하면 됩니다.

## 1. 점검표가 지금 동작과 반대로 적혀 있었습니다

`FIELD_CHECKLIST`의 C-11이 **2.3.0 시절 문장 그대로** 남아 있었습니다.

| | 적혀 있던 것 | 실제 |
|---|---|---|
| C-11 | 중간 행은 `정정`·`삭제`가 **잠겨 있다** | 2.3.1부터 **눌린다** |

같은 표의 C-12-1 ~ C-13-1이 정반대를 확인하고 있었습니다. 중간 박스를 고치는 절차를 점검하라고 해 놓고, 바로 위에서는 그게 잠겨 있어야 통과라고 한 것입니다. **새 PC를 까는 사람이 C-11에서 막혀 통과를 못 시킵니다.**

잠기는 조건을 확인하는 항목(C-11-1)을 따로 넣었습니다.

## 2. `정정` 버튼이 꺼지는 이유가 어디에도 없었습니다

`작업 완료`를 누른 작업은 잠깁니다. 박스를 선택해도 `정정`·`확정 취소`가 눌리지 않습니다.

이것이 **현장 카드에는 조건 없이** 적혀 있었습니다.

```text
이전:  어느 박스든 됩니다(어제 것도).
지금:  진행 중인 출고건이면 어느 박스든 됩니다(어제 것도).
       + 버튼이 눌리지 않으면 이미 작업 완료된 것입니다. 고장이 아닙니다.
```

버튼이 꺼진 것을 **고장으로 오인하는 것**을 막기 위한 것입니다. 사용 안내(F1)에도 같은 설명을 넣었습니다.

사용 안내에는 `진행 중인 출고건이면`이라는 조건이 이미 있었습니다만, **작업 완료를 누르면 그렇게 된다**는 연결이 없어 읽는 사람이 이어 붙이기 어려웠습니다.

> 고칠 것이 남았으면 **작업 완료를 누르지 않고** 둡니다.

## 3. 점검표를 두 갈래로 나눴습니다

점검표 맨 앞에 `2.3.0 작업 복구 추가 점검`이라는 목록이 **머리말보다 먼저** 붙어 있었습니다. "이 순서대로 확인한다"는 문장이 그 뒤에 나와서, 어디부터가 순서인지 알 수 없었습니다.

쓰는 상황이 둘인데 한 문서에 섞여 있던 것이 원인이었습니다. 갈라 놓았습니다.

| 상황 | 볼 곳 | 소요 |
|---|---|---|
| 이미 쓰던 PC에 **덮어 설치** | **U** | 20분 |
| **처음 까는 PC** | A ~ H | 반나절 |

`U`에는 2.3.2 ~ 2.3.3에서 바뀐 것만 담았습니다 — 숫자가 보이는지, 자리가 바뀌지 않는지, 국가 기본값, 항공·해상 번갈아 작업, 중간 박스 정정, 글자 크기, 기존 데이터 유지.

### U-7 — 지난 실적 무게 점검

관리자가 **1회만** 할 일을 점검표에 넣었습니다.

2.3.2 이전에는 친 숫자가 화면에 보이지 않았고, 그 상태에서 자리까지 바뀌어 들어갈 수 있었습니다. **무게가 열 배로 기록된 건이 남아 있을 수 있습니다.**

`출고건 Excel 저장` → 무게 열 내림차순 정렬 → 비정상적으로 큰 값 확인 → 실물·송장과 대조.

## 바뀐 문서

| 문서 | 어디서 보는가 | 바뀐 것 |
|---|---|---|
| `USER_MANUAL` | **프로그램 F1** | 작업 완료 시 잠김 설명 추가 |
| `OPERATOR_GUIDE` | 작업대에 붙이는 한 장 | 같은 내용 + 조건 보완 |
| `FIELD_CHECKLIST` | 새 PC 깔 때 | C-11 정정, U 신설 |

## 설치 방법

1. 작업관리자에서 실행 중인 `BeyondPack.exe`를 모두 종료합니다.
2. `BeyondPack-2.3.4-Windows-x64-Setup.exe`로 기존 버전 위에 설치합니다.
3. 이전 버전을 먼저 지울 필요는 없습니다. 덮어 설치하면 됩니다.
4. **F1**에서 `05. 정정과 확정 취소`에 작업 완료 설명이 있는지 확인합니다.

설치본에는 `BeyondPack-2.3.4-User-Guide.html`도 함께 들어갑니다. 인터넷 없이 열리므로 인쇄해서 작업대에 둘 수 있습니다.

기존 상품DB, 포장기록, 출고건 기록, 라벨·백업 설정은 모두 유지됩니다.
