# BeyondPack 2.2.5 사용자 매뉴얼

이 문서는 BeyondPack 2.2.5 설치형 Windows 프로그램의 현장 작업자·관리자 공용 매뉴얼이다. 프로그램은 Google Sheet의 상품정보를 내려받아 검증된 로컬 DB로 보관하고, 포장 작업 중에는 로컬 DB에서 `FNSKU+국가` 조합으로 상품을 조회한다.

## 1. 프로그램 운영 구조

```text
Google Sheet BeyondPack
        ↓ 시작 시 자동 다운로드 / F2 수동 업데이트
형식·필수값·중복·건수 검증
        ↓ 검증 성공 시 활성 포인터 전환
PC 로컬 상품DB 스냅샷(products.snapshot.*.db)
        ↓ 오프라인 조회
국가 선택 + FNSKU 스캔 → 포장정보 입력 → 작업 저장·라벨 출력
```

- 인터넷이 정상일 때: 실행 시 Google Sheet를 자동으로 확인하고 로컬 상품DB를 갱신한다.
- 인터넷이 끊겼을 때: 이전에 정상 저장된 로컬 상품DB로 계속 조회할 수 있다.
- 다운로드 또는 데이터 검증에 실패했을 때: 기존 정상 상품DB를 유지한다.
- Google Sheet를 사용할 수 없을 때: 관리자가 동일한 형식의 `.xlsx` 파일로 비상 업데이트할 수 있다.

## 2. 설치와 첫 실행

### 2.1 권장 설치 방법

1. GitHub Release에서 `BeyondPack-2.2.5-Windows-x64-Setup.exe`를 내려받는다.
2. 설치파일을 실행한다. 이 설치 방식은 일반 사용자 권한으로 설치할 수 있다.
3. 설치 화면에서 바탕화면 바로가기 생성을 유지하고 설치를 완료한다.
4. 바탕화면의 `BeyondPack` 아이콘을 실행한다.

Windows가 게시자를 확인할 수 없다고 표시할 수 있다. 현재 배포본은 회사 코드서명 적용 전이므로, 사내에서 배포한 GitHub Release 파일과 `SHA256SUMS.txt`의 해시가 일치하는지 확인한 뒤 실행한다.

### 2.2 처음 실행할 때 필요한 설정

1. 상단의 `Sheet 설정`을 누른다.
2. Google Sheet에서 `BeyondPack` 탭을 연 상태의 전체 주소를 복사해 붙여넣는다.
3. 확인하면 프로그램이 즉시 상품정보를 내려받고 검증한다.
4. 상단 상태가 `최신`으로 바뀌고 상품 건수와 국가 목록이 표시되는지 확인한다.
5. 정상 상품 하나를 국가별로 시험 스캔한다.

`상품DB 없음` 상태에서는 스캔 작업을 시작할 수 없다. 먼저 Sheet 주소를 설정해 업데이트하거나, 관리자가 `Excel 비상 업데이트`를 실행해야 한다.

## 3. 화면 구성

### 3.1 상단 공통 영역

| 항목 | 용도 |
|---|---|
| 작업 국가 | 이번 박스의 상품 국가를 선택한다. 같은 FNSKU도 국가가 다르면 다른 상품으로 조회된다. |
| 작업자 | 작업자 이름 또는 사번을 입력한다. 박스 확정 시 필수다. |
| 출고건 | 이번 출고 작업의 번호를 스캔·입력한다. 박스번호는 이 출고건 단위로 이어진다. 박스 확정 시 필수다. |
| 다음 #N | 지금 확정하면 나올 박스번호를 미리 보여준다. |
| F2 Google Sheet 업데이트 | Google Sheet의 최신 상품정보를 즉시 다운로드한다. |
| Sheet 설정 | `BeyondPack` 탭이 열린 Google Sheet 주소를 등록·변경한다. |
| 상품DB 상태 배너 | 최신 여부, DB 버전, 상품 건수, 마지막 업데이트 결과를 보여준다. |

### 3.2 작업 영역

- `1. 상품 스캔`: FNSKU를 스캔하고 품목명, 품목코드, SKU, FNSKU, 국가를 확인한다.
- `2. 박스 구성품`: 한 박스에 들어갈 단품 또는 합포 상품과 박스당 수량을 보여준다.
- `3. 포장정보 입력`: 박스수량, 박스당 무게, 가로, 세로, 높이를 작업자가 입력한다.
- 숫자 입력칸 오른쪽의 큰 `▲/▼` 버튼은 각각 값을 한 단계 올리고 내린다. 버튼을 계속 누르면 연속 증감한다.
- `다음 행동`: 현재 단계에서 해야 할 작업 또는 오류 해결 방향을 표시한다.

### 3.3 상품DB 상태의 의미

| 상태 | 의미 | 작업 가능 여부 |
|---|---|---|
| 최신 | 방금 업데이트한 상품DB가 검증을 통과했다. | 가능 |
| 캐시 사용 중 | 기존 로컬 상품DB를 사용 중이다. 인터넷 장애 또는 오래된 DB일 수 있다. | 상품DB가 있으면 가능 |
| 업데이트 중 | Google Sheet 또는 Excel을 다운로드·검증하고 있다. | 기존 DB 조회는 가능하지만 설정 변경은 기다린다. |
| 오류 | 최신 업데이트에 실패했다. 오류 메시지를 확인한다. | 기존 정상 DB가 있으면 가능 |
| 상품DB 없음 | 이 PC에 사용할 수 있는 상품정보가 한 건도 없다. | 불가능 |

## 4. 기본 포장 작업

### 4.1 작업 시작

1. BeyondPack을 실행한다.
2. 상품DB 상태와 상품 건수를 확인한다.
3. `작업 국가`를 선택한다.
4. `작업자`에 이름 또는 사번을 입력한다.
5. `출고건`에 이번 출고 작업의 번호를 스캔하거나 입력한다.
6. 옆의 `다음 #N` 표시로 이번 작업의 시작 박스번호를 확인한다.

국가는 첫 상품을 박스 구성에 추가한 뒤에는 변경할 수 없다. 국가를 잘못 선택했다면 `F4 현재 입력 초기화`로 구성품을 비운 뒤 다시 선택한다.

### 4.2 단품 박스 등록

1. FNSKU 입력칸에 포커스가 있는지 확인하고 바코드를 스캔한다. 스캐너가 Enter를 보내면 자동 조회된다.
2. 표시된 `품목명·품목코드·SKU·FNSKU·국가`가 실물과 일치하는지 확인한다.
3. `박스당 상품수량`에 한 박스에 들어가는 EA 수량을 입력한다.
4. `합포 구성에 추가`를 누른다. 단품도 반드시 구성품에 추가해야 한다.
5. `박스수량`에 동일한 구성과 포장규격으로 만들 박스 수를 입력한다.
6. `무게`는 박스 1개 기준 kg, `가로·세로·높이`는 박스 1개 기준 cm로 입력한다.
7. `Ctrl+Enter 박스 확정`을 누른다.
8. 저장 완료 메시지와 생성된 박스 번호 범위를 확인한다.
9. 라벨이 박스수량만큼 자동 출력된다. 다시 뽑으려면 `F8 마지막 라벨 재출력`을 누른다.

### 4.3 합포 박스 등록

1. 첫 번째 FNSKU를 조회하고 박스당 수량을 입력한 뒤 `합포 구성에 추가`를 누른다.
2. 다음 FNSKU를 스캔하고 같은 과정을 반복한다.
3. `박스 구성품` 표에서 모든 FNSKU, 품목코드, SKU, 국가, 품목명, EA/BOX를 대조한다.
4. 잘못 추가한 상품은 해당 행을 선택하고 `선택 상품 제거`를 누른다.
5. 박스수량과 박스당 포장정보를 입력한 뒤 `Ctrl+Enter`로 확정한다.
6. 라벨이 박스수량만큼 자동 출력된다. 필요하면 `F8`로 재출력한다.

같은 FNSKU를 다시 추가하면 기존 수량에 더할지 묻는다. `예`를 선택하면 두 입력 수량이 합산되고, `아니요`를 선택하면 기존 수량을 유지한다.

### 4.4 여러 박스를 한 번에 확정하는 기준

`박스수량`을 2 이상으로 입력하면 다음 정보가 모두 동일한 박스 묶음으로 저장된다.

- 구성 FNSKU와 각 상품의 EA/BOX
- 박스 1개당 무게
- 박스 1개당 가로·세로·높이

박스별 구성이나 규격이 하나라도 다르면 각각 별도 작업으로 확정해야 한다.

## 5. 라벨 설정과 출력

### 5.1 라벨 설정 (설치 후 한 번)

1. `라벨 설정`을 누른다.
2. 현장 라벨 프린터를 고른다.
3. 라벨 롤의 **실제 크기**를 가로·세로 mm로 입력한다. 현장 기본값은 `40 × 25mm`다.
4. `박스 확정과 동시에 라벨을 자동 출력한다`를 켜둔다.
5. 저장한 뒤 `테스트 라벨 출력`으로 확인한다.

크기를 잘못 넣으면 내용이 잘리거나 빈 라벨이 함께 배출된다. 이때는 라벨 롤을 자로 재서 다시 입력한다.

### 5.2 출력과 재출력

- 라벨 프린터를 지정해 두면 박스를 확정하는 즉시 **박스수량만큼** 라벨이 자동 출력된다.
- 다시 뽑을 때는 `F8 마지막 라벨 재출력`을 누른다.
- 라벨 프린터를 지정하지 않았다면 출력할 때마다 Windows 인쇄창이 열린다.

40×25mm 라벨에는 출고건, 박스번호(`#1`, `#2` …), 전체 장수(`1 / 8`), 품목코드·수량·무게가 인쇄된다. 박스수량 8개를 확정하면 `#1`부터 `#8`까지 8장이 순번대로 나온다. 합포는 `합포 3품목 · 45EA`로 요약되며 전체 구성품 내역은 포장실적 Excel에 남는다.

높이 40mm 이상 라벨을 지정하면 FNSKU·품목코드·SKU·국가·EA 표가 함께 인쇄된다.

프린터 오류가 발생해도 박스를 다시 등록하지 말고 프린터를 복구한 뒤 F8을 다시 누른다. 새 박스를 확정하면 F8의 대상도 새로 확정한 박스로 바뀐다.

### 5.3 박스번호 규칙

박스번호는 **출고건 단위**로 매겨진다.

| 상황 | 박스번호 |
|---|---|
| 출고건 `FBA15ABC`로 3박스 확정 | `#1` `#2` `#3` |
| 프로그램을 껐다 켜고 같은 출고건으로 확정 | `#4`부터 이어짐 |
| 출고건을 `FBA15XYZ`로 바꿔 확정 | `#1`부터 다시 시작 |
| 다시 `FBA15ABC`로 되돌아가 확정 | 그 출고건의 다음 번호부터 이어짐 |

출고건을 입력하지 않으면 박스를 확정할 수 없다. 출고건 칸 옆의 `다음 #N` 표시로 확정 전에 번호를 확인한다.

박스번호는 작업 PC 안에서만 이어진다. 같은 출고건을 여러 작업대가 나눠 작업하면 번호가 겹치므로, 한 출고건은 한 작업대에서 처리한다.

## 6. 상품정보 업데이트

### 6.1 자동 업데이트

프로그램은 실행할 때마다 설정된 Google Sheet에서 CSV를 자동 다운로드한다. 검증에 성공해야만 로컬 상품DB가 교체된다. 실제 바코드 조회는 Google Sheet를 매번 검색하지 않고 로컬 DB에서 수행하므로 현장 스캔 속도는 인터넷 상태의 영향을 받지 않는다.

### 6.2 F2 수동 업데이트

다음 상황에서는 `F2`를 한 번 누른다.

- 방금 Google Sheet에 신규 상품 또는 수정사항을 반영한 경우
- 신규 FNSKU가 미등록으로 표시되는 경우
- 프로그램 시작 당시 인터넷이 끊겼다가 복구된 경우

업데이트 후 상태 배너의 상품 건수와 DB 버전을 확인한다. F2를 여러 번 연속해서 누를 필요는 없다.

### 6.3 Excel 비상 업데이트

Google Sheet 장애가 길어질 때 관리자만 사용한다.

1. Google Sheet의 정상 마스터를 `.xlsx`로 내려받거나 같은 형식의 파일을 준비한다.
2. 시트 이름은 `BeyondPack`을 사용한다. 기존 `BeyondPack_Master`도 호환하며, 둘 다 없으면 프로그램이 첫 번째 시트를 읽는다.
3. `Excel 비상 업데이트`를 누르고 파일을 선택한다.
4. 안내창에서 계속 여부를 확인한다.
5. 검증 완료 후 상품 건수와 상태를 확인한다.

Excel을 적용해도 Google Sheet 주소와 다음 실행 시 자동 업데이트 설정은 유지된다.

## 7. 미완료 작업 복구와 초기화

- 구성품이나 포장정보를 입력하면 프로그램이 임시저장한다.
- 비정상 종료 후 다시 실행하면 `미완료 작업 복구` 여부를 묻는다.
- `예`: 국가, 구성품, 박스수량, 포장정보를 복구한다. 내용과 작업자 정보를 다시 확인한 후 확정한다.
- `아니요`: 해당 미완료 입력을 삭제한다.
- `F4 현재 입력 초기화`: 아직 확정하지 않은 구성품과 포장정보를 모두 지운다. 저장이 끝난 과거 작업은 삭제하지 않는다.

## 8. 포장실적 Excel 저장

1. 저장할 작업을 현재 프로그램에서 한 건 이상 확정한다.
2. `작업 Excel 저장`을 누른다.
3. 파일명과 저장 위치를 선택한다.
4. 완료 메시지의 구성품 행 수를 확인한다.

Excel에는 포장 작업, 박스 그룹, 구성품, 작업 당시의 상품정보와 상품DB 버전이 포함된다. 현재 실행에서 생성한 작업 단위로 저장되므로 교대 또는 작업 구간 종료 시 내보내는 운영을 권장한다.

## 9. Google Sheet 관리자 기준

### 9.1 필수 열

`BeyondPack` 탭 첫 행에 다음 내부 열 이름을 사용한다.

```text
FNSKU,ItemCode,SKU,CountryCode,ProductName,ProductNameEn,AmazonAccount,Status,SourceModifiedAt,DataVersion,SchemaVersion
```

필수값은 `FNSKU`, `ItemCode`, `SKU`, `CountryCode`, `ProductName`이다. 화면의 국가는 `CountryCode`를 사용한다. 기존 파일의 `CountryName` 열은 있어도 읽지만 신규 Google Sheet에는 만들지 않는다. `SchemaVersion`은 현재 `2`를 사용한다. 활성 상품의 `Status`는 `Published`, `Active`, `Y` 중 하나를 사용한다.

### 9.2 국가별 FNSKU 등록

FNSKU가 같아도 국가가 다르면 국가별로 한 행씩 등록한다.

```text
FNSKU       CountryCode
X001ABC123  US
X001ABC123  CA
X001ABC123  JP
```

동일한 `FNSKU+CountryCode` 조합은 중복 등록할 수 없다. 프로그램은 이 조합을 내부 조회키로 사용한다.

### 9.3 변경 반영 절차

1. 담당자가 Google Sheet를 수정한다.
2. FNSKU, 국가코드, 품목코드, SKU 등 필수값과 중복 여부를 검토한다.
3. `SourceModifiedAt`과 `DataVersion` 운영값을 갱신한다. DataVersion이 비어 있으면 프로그램이 내용 기반 버전을 자동 생성한다.
4. 포장 PC에서 F2를 누른다.
5. 상품 건수와 대표 변경 상품을 조회해 확인한다.

전체 상품 수가 기존 DB보다 20% 이상 감소하거나 필수 열·필수값·중복·스키마에 문제가 있으면 업데이트가 차단되고 기존 DB가 유지된다.

## 10. 오류별 대응

| 화면 메시지 또는 상황 | 원인 | 조치 |
|---|---|---|
| 먼저 작업 국가를 선택하세요 | 국가가 선택되지 않았다. | 상단 작업 국가를 선택한 뒤 다시 스캔한다. |
| 미등록 FNSKU | 선택한 국가의 로컬 DB에 해당 FNSKU가 없다. | 국가를 확인하고 F2 업데이트 후 재조회한다. |
| 다른 국가에만 등록됨 | FNSKU는 있으나 선택 국가와 다르다. | 오류에 안내된 등록 국가와 실물을 확인한다. |
| 상품DB 없음 | 최초 업데이트가 없거나 로컬 DB를 사용할 수 없다. | Sheet 설정 및 네트워크를 확인하거나 Excel 비상 업데이트를 실행한다. |
| 캐시 사용 중 | 최신 다운로드 실패 또는 DB가 권장 사용시간보다 오래됐다. | 기존 DB로 작업 가능하나 관리자에게 알리고 F2 재시도한다. |
| Google Sheet 필수 열이 없습니다 | 첫 행 열 이름이 틀렸거나 다른 탭 URL이다. | `BeyondPack` 탭과 필수 열 이름을 확인한다. |
| 동일 FNSKU+국가 중복 | 같은 조회키가 두 행 이상 있다. | 중복 행을 정리한 뒤 F2를 다시 누른다. |
| 상품 수 급감으로 업데이트 차단 | 새 데이터가 기존보다 20% 이상 줄었다. | 필터·삭제·CSV 공개 범위를 확인하고 정상 건수를 복원한다. |
| 다른 프로세스가 파일을 사용 중입니다 / WinError 32 | 구버전이 고정 `products.db`를 교체하려 했거나 외부 프로그램이 파일을 잠갔다. | 2.2.3 이상으로 업데이트한다. 새 버전은 잠긴 파일을 덮어쓰지 않고 별도 스냅샷으로 전환한다. |
| 수량 화살표가 반응하지 않음 | 구버전 기본 스핀박스의 클릭영역 문제다. | 2.2.3 이상에서 숫자칸 오른쪽의 큰 `▲/▼` 버튼을 사용한다. |
| 박스에 상품을 한 개 이상 추가하세요 | 조회만 하고 구성품에 추가하지 않았다. | 박스당 수량 입력 후 `합포 구성에 추가`를 누른다. |
| 작업자 이름 또는 사번을 입력하세요 | 작업자 정보가 비어 있다. | 상단 작업자 입력 후 다시 확정한다. |
| 무게/규격 오류 | 값이 0이거나 허용 범위를 벗어났다. | 실측값과 단위(kg/cm)를 확인한다. |
| 재출력할 저장된 라벨이 없습니다 | 현재 실행에서 확정한 박스가 없다. | 먼저 박스를 확정한다. |
| 출고건 번호를 입력하세요 | 출고건 칸이 비어 있다. | 상단 `출고건`에 번호를 입력한 뒤 확정한다. |
| 설정된 라벨 프린터를 찾을 수 없습니다 | 지정한 프린터가 꺼져 있거나 이름이 바뀌었다. | `라벨 설정`에서 프린터를 다시 고른다. |
| 라벨이 잘리거나 빈 라벨이 나온다 | 라벨 크기 설정이 실제 롤과 다르다. | 라벨 롤을 자로 재서 `라벨 설정`에 mm로 입력한다. |

오류 메시지 끝의 `BP-...` 코드는 관리자에게 전달할 때 함께 기록한다.

## 11. 관리자 진단파일

문제가 반복되면 `관리자 진단파일 생성`을 누른다. 바탕화면에 진단 ZIP이 생성된다. 이 파일에는 인증정보와 상품·포장 원문은 포함하지 않으며, 설정 요약과 동기화 상태·로그 등 문제 분석에 필요한 정보가 포함된다.

관리자에게 다음 정보를 함께 전달한다.

- 발생 시각
- 작업 PC 이름 또는 위치
- 선택 국가와 스캔한 FNSKU
- 화면 오류 문구와 BP 오류코드
- 재현 순서
- 생성된 진단 ZIP

## 12. 데이터 위치와 백업

기본 저장 위치는 다음과 같다.

```text
%LOCALAPPDATA%\BeyondPack\config.json
%LOCALAPPDATA%\BeyondPack\data\products.current.json
%LOCALAPPDATA%\BeyondPack\data\products.snapshot.<PID>.<UUID>.db
%LOCALAPPDATA%\BeyondPack\data\packaging.db
%LOCALAPPDATA%\BeyondPack\data\sync-status.json
%LOCALAPPDATA%\BeyondPack\logs\startup.log
```

- `products.current.json`: 현재·직전 상품DB 스냅샷 이름을 가리키는 포인터
- `products.snapshot.*.db`: 현재와 직전 정상 상품 캐시. 오래된 스냅샷은 자동 정리
- `products.db`, `products.previous.db`: 업그레이드 호환용 기존 캐시. 새 버전은 잠겨 있어도 덮어쓰지 않음
- `packaging.db`: 확정 작업과 미완료 입력
- `config.json`: Google Sheet 주소와 운영 설정

프로그램 업데이트 또는 제거 시에도 위 사용자 데이터는 자동 삭제하지 않는다. PC 교체·초기화 전에는 BeyondPack을 종료한 상태에서 `%LOCALAPPDATA%\BeyondPack` 폴더를 사내 보안 저장소에 백업한다. 포장기록이 있는 `packaging.db`를 임의로 삭제하거나 여러 PC에서 동시에 덮어쓰지 않는다.

## 13. 업데이트와 제거

### 프로그램 업데이트

1. 현재 작업을 확정하고 필요한 실적을 Excel로 저장한다.
2. BeyondPack을 종료한다.
3. 새 버전의 Setup 파일을 실행해 설치한다.
4. 실행 후 버전, 상품DB 상태, 국가 목록, 테스트 스캔, 테스트 라벨을 확인한다.

### 프로그램 제거

Windows `설정 → 앱 → 설치된 앱 → BeyondPack → 제거`를 사용한다. 사용자 데이터는 보존되므로 완전 삭제가 필요한 경우에만 백업과 보존기한을 확인한 뒤 `%LOCALAPPDATA%\BeyondPack`을 별도로 정리한다.

## 14. 현장 권장 점검표

### 작업 시작 전

- 프로그램 버전과 상품DB 상태·건수 확인
- 작업 국가와 작업자 확인
- 정상 FNSKU 1건 시험 조회
- 스캐너 Enter 입력 확인
- 라벨 프린터, 용지, 인쇄 방향 확인

### 박스 확정 전

- 실물과 품목명·품목코드·SKU·FNSKU·국가 일치
- 합포 구성품과 EA/BOX 일치
- 박스수량 확인
- 무게는 kg/BOX, 규격은 cm 기준 확인

### 작업 종료 시

- 마지막 박스 저장·라벨 출력 확인
- 포장실적 Excel 저장
- 오류나 예외 작업을 교대자·관리자에게 인계
