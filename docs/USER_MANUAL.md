# BeyondPack 2.2.9 사용자 매뉴얼

현장 작업자와 관리자가 함께 쓰는 문서다. 1~8장은 작업자용, 9~14장은 관리자용이다.

설치 직후에는 이 문서 대신 [현장 도입 점검표](FIELD_CHECKLIST.md)를 먼저 따른다.

---

## 1. 이 프로그램이 하는 일

Google Sheet의 상품 마스터를 내려받아 **검증을 통과한 것만** PC 안에 상품DB로 보관하고, 포장 작업 중에는 인터넷 없이 그 상품DB에서 `FNSKU + 작업 국가`로 상품을 조회한다. 확정한 박스는 PC 안에 기록되고 라벨이 출력된다.

```text
Google Sheet BeyondPack 탭
      ↓ 프로그램 시작 시 자동 · 작업 중 F2
형식 · 필수값 · 중복 · 급감 검증
      ↓ 전부 통과했을 때만 교체
PC 로컬 상품DB
      ↓ 인터넷 없이 조회
국가 선택 → 출고건 입력 → FNSKU 스캔 → 포장정보 입력 → 박스 확정 → 라벨 출력
```

| 상황 | 프로그램 동작 |
|---|---|
| 인터넷 정상 | 시작할 때 자동으로 최신 상품정보를 받아 교체한다 |
| 인터넷 끊김 | 마지막으로 검증에 성공한 상품DB로 계속 작업한다 |
| 다운로드·검증 실패 | 기존 상품DB를 그대로 유지한다. 잘못된 데이터가 현장에 내려가지 않는다 |
| Google Sheet 장애 | 관리자가 같은 형식의 `.xlsx`로 비상 업데이트한다 |

## 2. 설치와 최초 설정

설치 후 **한 번만** 하면 되는 작업이다. 순서를 지켜야 한다.

### 2.1 설치

1. GitHub Release에서 `BeyondPack-2.2.9-Windows-x64-Setup.exe`를 내려받는다.
2. 실행해서 설치한다. 관리자 권한은 필요 없다.
3. 바탕화면 바로가기 생성을 유지한다.
4. 바탕화면의 `BeyondPack`을 실행한다. 창 제목이 `BeyondPack 2.2.9 · BEYOND EARTH`인지 확인한다.

Windows가 게시자를 확인할 수 없다고 경고할 수 있다. 현재 배포본은 회사 코드서명 전이므로, 사내에서 배포한 파일과 `SHA256SUMS.txt`의 해시가 같은지 확인하고 실행한다.

### 2.2 상품 마스터 연결

1. 상단 `Sheet 설정`을 누른다.
2. Google Sheet에서 `BeyondPack` 탭을 연 상태의 주소를 통째로 붙여넣는다.
3. 확인하면 즉시 다운로드·검증이 시작된다.
4. 상태 배너가 `최신`으로 바뀌고 상품 건수가 표시되는지, `작업 국가` 목록이 채워지는지 확인한다.

### 2.3 라벨 프린터 등록 — 건너뛰면 라벨이 잘린다

**먼저 Windows 드라이버에 라벨 크기를 등록한다.** 이 등록이 없으면 프로그램이 크기를 지정해도 드라이버가 거부하고 A4로 인쇄해, 잘린 라벨 뒤에 빈 라벨이 계속 나온다.

1. Windows `설정 > Bluetooth 및 장치 > 프린터 및 스캐너`에서 라벨 프린터를 연다.
2. `인쇄 기본 설정`(또는 `프린터 속성 > 기본 설정`)을 연다.
3. 용지 크기에서 `40 x 25mm`를 고른다. 없으면 `사용자 정의`로 폭 40mm, 높이 25mm를 추가한다.

그다음 프로그램에서 설정한다.

1. `설정·관리자 도구 > 라벨 설정`을 연다.
2. 현장 라벨 프린터를 고른다.
3. 라벨 롤의 **실제 크기**를 mm로 넣는다. 현장 기본값은 `40 × 25mm`다.
4. 안내줄 색을 확인한다.

| 색 | 뜻 | 조치 |
|---|---|---|
| 초록 | `이 프린터에 40×25mm 용지가 등록되어 있습니다` | 그대로 저장 |
| 노랑 | 드라이버에 그 크기가 없다(등록된 크기 목록을 함께 보여준다) | 위의 드라이버 등록을 먼저 끝낸다 |
| 빨강 | 프린터를 찾을 수 없다 | 전원·연결·프린터 이름 확인 |

5. `박스 확정과 동시에 라벨을 자동 출력한다`를 켜고 저장한다.
6. `설정·관리자 도구 > 테스트 라벨 출력`으로 `#1`, `#2` 두 장이 잘리지 않고 나오는지 확인한다.

### 2.4 자동 백업 — 건너뛰면 실적이 이 PC에만 남는다

포장 실적은 이 PC의 `packaging.db`에만 저장된다. 디스크가 고장나면 복구할 수 없으므로 **PC마다 반드시 지정한다.** 같은 설정으로 상품 마스터 사본도 함께 보관된다.

1. `설정·관리자 도구 > 자동 백업 설정`을 연다.
2. `포장 실적을 지정한 위치에 자동으로 복사한다`를 켠다.
3. **백업 위치**를 고른다. 공유 드라이브(`\\서버\물류\BeyondPack`)나 동기화 폴더를 권장한다.
4. 백업 주기(기본 10분)와 사본 보관일수(기본 90일)를 정한다.
5. 저장하면 즉시 한 번 백업한다. 배너 오른쪽이 **`백업 HH:MM`(초록)** 이 되는지 확인한다.
6. 백업 위치에 `<PC이름>` 폴더와 `packaging.db`, 당일 CSV가 생겼는지 확인한다.
7. 같은 위치의 `products` 폴더에 `products-날짜-버전.xlsx`가 생겼는지 확인한다. 이게 상품 마스터 사본이다.

배너가 `백업 미설정`(빨강)이면 그 PC는 보호되지 않은 상태다. 자세한 내용은 12장을 참고한다.

## 3. 화면 구성

### 3.1 상단

| 항목 | 용도 |
|---|---|
| 작업 국가 | 이번 박스의 상품 국가. 같은 FNSKU라도 국가가 다르면 다른 상품으로 조회된다 |
| 작업자 | 이름 또는 사번. 박스 확정 시 필수 |
| 출고건 | 이번 출고 작업의 문서번호. **박스번호가 이 단위로 이어진다.** 확정 시 필수 |
| 다음 #N | 지금 확정하면 붙을 박스번호를 미리 보여준다 |
| F2 상품 업데이트 | 최신 상품정보를 즉시 내려받는다 |
| Sheet 설정 | Google Sheet 주소를 등록·변경한다 |

### 3.2 상품DB 상태 배너

| 상태 | 뜻 | 작업 가능 |
|---|---|---|
| 최신 | 방금 받은 상품정보가 검증을 통과했다 | 가능 |
| 캐시 사용 중 | 기존 상품DB로 작업 중이다. 인터넷 장애이거나 DB가 오래됐다 | 가능 |
| 업데이트 중 | 다운로드·검증 진행 중 | 조회는 가능, 설정 변경은 대기 |
| 오류 | 최신 업데이트에 실패했다 | 기존 DB가 있으면 가능 |
| 상품DB 없음 | 이 PC에 쓸 수 있는 상품정보가 없다 | **불가능** |

배너 오른쪽에는 **백업 상태**가 함께 표시된다.

| 표시 | 뜻 |
|---|---|
| `백업 02:41`(초록) | 그 시각에 실적 사본이 백업 위치에 저장됐다 |
| `백업 실패`(빨강) | 백업 위치에 쓰지 못했다. 마우스를 올리면 이유가 나온다. **작업은 계속해도 된다** |
| `백업 대기`(회색) | 설정은 됐고 아직 이번 실행에서 백업하지 않았다 |
| `백업 미설정`(빨강) | 실적이 이 PC에만 있다. 관리자가 백업 위치를 지정해야 한다 |

### 3.3 작업 영역

- **1. 상품 스캔** — FNSKU를 스캔하고 품목명·품목코드·SKU·FNSKU·국가를 확인한다. 박스당 상품수량을 넣고 `합포 구성에 추가`를 누른다.
- **2. 박스 구성품**(탭) — 이 박스에 담길 상품 목록을 `품목코드·FNSKU·국가·품목명·EA/BOX`로 보여준다. 잘못 넣었으면 행을 선택하고 `선택 상품 제거`.
- **3. 포장정보 입력** — 박스수량, 박스당 무게·가로·세로·높이. **박스수량은 입력 전까지 빈칸**이며 빈칸으로는 확정할 수 없다.
- **4. 출고건 작업 현황**(탭) — 이 출고건에서 지금까지 확정한 박스가 쌓인다. 박스를 확정하면 자동으로 이 탭이 열린다.
- **다음 행동** — 지금 해야 할 일 또는 오류 해결 방향을 알려준다. 초록은 정상, 빨강은 확인 필요다.

숫자 입력칸 오른쪽의 큰 `▲/▼`로 값을 올리고 내린다. 길게 누르면 연속으로 변한다.

### 3.4 작업 도구

| 버튼 | 용도 |
|---|---|
| F4 현재 입력 초기화 | 아직 확정하지 않은 구성품과 포장정보를 지운다. 저장된 박스는 지우지 않는다 |
| F8 마지막 라벨 재출력 | 마지막에 확정한 박스의 라벨을 다시 뽑는다 |
| 출고건 Excel 저장 | 이 출고건 **전체** 실적을 Excel로 저장한다 |
| 설정·관리자 도구 ▾ | 자동 백업 설정 · 지금 백업 · 라벨 설정 · 테스트 라벨 출력 · Excel 비상 업데이트 · 관리자 진단파일 생성 |

## 4. 하루 작업 흐름

### 4.1 작업 시작

1. BeyondPack을 실행한다.
2. 상태 배너와 상품 건수를 확인한다.
3. `작업 국가`를 고른다.
4. `작업자`에 이름 또는 사번을 넣는다.
5. `출고건`에 문서번호를 스캔하거나 입력한다. **몇 글자만 치면 최근 사용한 출고건이 목록으로 뜨므로 목록에서 고른다.**
6. `다음 #N`을 확인한다. 이어작업인데 `다음 #1`이 뜨면 **문서번호를 잘못 입력한 것**이다.

국가는 첫 상품을 구성품에 추가한 뒤에는 바꿀 수 없다. 잘못 골랐다면 `F4`로 비우고 다시 고른다.

### 4.2 단품 박스

1. FNSKU 입력칸에 커서를 두고 바코드를 스캔한다. 스캐너가 Enter를 보내면 자동 조회된다.
2. 화면의 `품목명·품목코드·SKU·FNSKU·국가`가 실물과 맞는지 확인한다.
3. `박스당 상품수량`에 한 박스에 들어가는 EA를 넣는다.
4. `합포 구성에 추가`를 누른다. **단품도 반드시 추가해야 한다.**
5. `박스수량`에 같은 구성·같은 규격으로 만들 박스 수를 넣는다.
6. `무게`는 박스 1개 기준 kg, `가로·세로·높이`는 박스 1개 기준 cm로 넣는다.
7. `Ctrl+Enter`로 확정한다.
8. 라벨이 박스수량만큼 자동 출력되고, 화면이 `4. 출고건 작업 현황` 탭으로 바뀌며 방금 확정한 박스가 목록에 추가된다.

### 4.3 합포 박스

1. 첫 FNSKU를 조회하고 수량을 넣어 `합포 구성에 추가`.
2. 다음 FNSKU를 스캔해 같은 과정을 반복한다.
3. `2. 박스 구성품` 탭에서 품목코드·FNSKU·국가·품목명·EA/BOX를 전부 대조한다.
4. 잘못 넣은 상품은 행을 선택하고 `선택 상품 제거`.
5. 포장정보를 넣고 `Ctrl+Enter`로 확정한다.

같은 FNSKU를 다시 추가하면 기존 수량에 더할지 묻는다. `예`면 합산, `아니요`면 기존 수량 유지다.

### 4.4 박스수량을 2 이상으로 넣는 기준

다음이 **모두 같을 때만** 한 번에 확정한다.

- 구성 FNSKU와 각 상품의 EA/BOX
- 박스 1개당 무게
- 박스 1개당 가로·세로·높이

하나라도 다르면 나눠서 확정한다.

## 5. 박스번호 규칙

박스번호는 **출고건 단위**로 이어진다. 날짜나 프로그램 실행과는 무관하다.

| 상황 | 결과 |
|---|---|
| 출고건 `1B`로 3박스 확정 | `#1` `#2` `#3` |
| 프로그램을 껐다 켜고 같은 출고건으로 확정 | `#4`부터 이어짐 |
| 다음 날 같은 출고건으로 재개 | 마지막 번호 다음부터 이어짐 |
| 출고건을 `2B`로 바꿔 확정 | `#1`부터 다시 시작 |
| 다시 `1B`로 돌아와 확정 | `1B`의 다음 번호부터 이어짐 |

대소문자와 공백은 무시한다. `1B`, `1b`, `1 B`는 모두 같은 출고건이다.

**주의.** 문서번호가 한 글자라도 다르면(`1B` → `1B-2`) 다른 출고건으로 보고 `#1`부터 시작한다. 확정 전에 `다음 #N`을 반드시 확인한다.

박스번호는 **이 PC 안에서만** 이어진다. 같은 출고건을 여러 작업대가 나눠 작업하면 번호가 겹친다. **한 출고건은 한 작업대에서 처리한다.**

## 6. 라벨

### 6.1 인쇄되는 내용

40×25mm 기준이다.

```text
1B                    1 / 8      ← 출고건, 전체 중 몇 번째
#1                               ← 박스번호
X003ABC123 · 15EA · 10.0kg       ← FNSKU, 수량, 박스 무게
```

- 화면 현황 표와 라벨 모두 **FNSKU**를 쓴다. 작업자가 스캔한 값과 같으므로 실물 대조가 바로 된다.
- 합포는 `합포 3품목 · 45EA · 10.0kg`으로 요약된다. **전체 구성품 내역은 포장실적 Excel에 남는다.**
- 높이 40mm 이상 라벨을 지정하면 FNSKU·품목코드·SKU·국가·EA 표가 함께 인쇄된다.
- 내용이 라벨보다 길면 자동으로 축소해 한 장 안에 담는다. 박스 1개에 라벨은 항상 1장이다.

### 6.2 출력과 재출력

- 라벨 프린터를 지정해 두면 **박스를 확정하는 즉시 박스수량만큼** 자동 출력된다.
- 방금 확정한 박스를 다시 뽑으려면 `F8`.
- **지난 박스를 다시 뽑으려면** `4. 출고건 작업 현황` 탭에서 그 행을 선택하고 `선택 박스 라벨 재출력`.
- 라벨 프린터를 지정하지 않았다면 출력할 때마다 Windows 인쇄창이 열린다.

프린터 오류가 나도 **박스를 다시 등록하지 않는다.** 프린터를 복구한 뒤 재출력하면 된다.

## 7. 출고건 작업 현황과 Excel 저장

### 7.1 현황 확인

`4. 출고건 작업 현황` 탭에서 본다.

- 박스를 확정할 때마다 내역이 누적되고 화면이 이 탭으로 자동 전환된다.
- 표 위 요약: `출고건 1B · 확정 9박스 · 총 중량 95.0 kg · 다음 박스 #10`
- 탭 제목에도 박스 수가 표시되어 탭을 열지 않아도 진행량을 알 수 있다.
- 표 항목: 박스번호 · **FNSKU** · EA/BOX · 무게 · 규격 · 확정시각. 합포는 `합포 N품목`으로 표시된다
- 프로그램을 껐다 켜도 같은 출고건을 넣으면 지난 내역이 그대로 다시 보인다.

### 7.2 마지막 박스 수정·삭제

잘못 확정한 박스는 현황 탭에서 되돌릴 수 있다. **출고건의 마지막 박스만** 가능하다. 중간 박스를 지우면 이미 붙인 라벨의 번호와 이후 번호가 어긋나기 때문이다. 중간 행을 선택하면 두 버튼이 회색으로 잠기고, 마우스를 올리면 이유가 나온다.

**수정** — 확정을 되돌려 입력칸으로 되살린다.

1. 현황 탭에서 **마지막 행**을 선택하고 `선택 박스 수정`을 누른다.
2. 사유를 입력한다. 기록에 남으므로 비워 둘 수 없다.
3. 구성품·박스수량·포장정보가 입력칸으로 돌아오고 `2. 박스 구성품` 탭이 열린다.
4. 고칠 값을 바꾼 뒤 `Ctrl+Enter`로 다시 확정한다. **같은 박스번호**가 다시 붙는다.

**삭제** — 확정을 되돌리고 버린다.

1. 마지막 행을 선택하고 `선택 박스 삭제`를 누른다.
2. 사유를 입력한다.
3. 박스가 목록에서 사라지고 `다음 #N`이 그 번호로 되돌아간다.

> **이미 출력한 라벨은 반드시 폐기한다.** 프로그램이 되돌려도 인쇄된 종이는 그대로 남는다.
>
> 작성 중인 구성품이 있으면 수정할 수 없다. 먼저 확정하거나 `F4`로 비운다.

수정·삭제는 **사유와 함께 기록**된다. 누가 언제 무엇을 왜 되돌렸는지 남으므로, 실수를 숨기지 말고 사유를 정확히 적는다.

### 7.3 Excel 저장

1. 출고건 번호가 들어 있는지 확인한다.
2. `출고건 Excel 저장`을 누른다.
3. 파일명과 위치를 고른다.

**그 출고건 전체**가 저장된다. 여러 날에 걸쳐 이어서 작업했더라도 모든 박스가 한 파일에 담긴다. 첫 열이 `출고건`이며, 박스 그룹·구성품·작업 당시 상품정보·상품DB 버전이 포함된다.

교대 종료 또는 출고건 완료 시 저장해 두기를 권장한다. **포장기록은 이 PC에만 있으므로, PC가 고장나면 저장해 두지 않은 실적은 복구할 수 없다.**

## 8. 미완료 작업 복구와 초기화

- 구성품이나 포장정보를 입력하면 자동으로 임시저장된다.
- 비정상 종료 후 다시 실행하면 `미완료 작업 복구` 여부를 묻는다.
  - `예`: 출고건·국가·구성품·박스수량·포장정보를 되살린다. 내용을 다시 확인한 뒤 확정한다.
  - `아니요`: 임시저장을 지운다.
- `F4`는 **아직 확정하지 않은** 입력만 지운다. 이미 확정한 박스는 영향받지 않는다.

## 9. 상품정보 업데이트 (관리자)

### 9.1 자동 업데이트

프로그램은 실행할 때마다 Google Sheet CSV를 자동으로 내려받는다. 검증을 전부 통과해야만 상품DB가 교체된다. 실제 스캔 조회는 로컬 DB에서 하므로 현장 속도는 인터넷 상태와 무관하다.

### 9.2 F2 수동 업데이트

- 방금 Sheet에 신규 상품이나 수정사항을 넣은 경우
- 신규 FNSKU가 미등록으로 뜨는 경우
- 시작할 때 인터넷이 끊겼다가 복구된 경우

누른 뒤 배너의 상품 건수와 DB 버전을 확인한다. 여러 번 연속으로 누를 필요는 없다.

### 9.3 Excel 비상 업데이트

Google Sheet 장애가 길어질 때 **관리자만** 사용한다.

1. 정상 마스터를 `.xlsx`로 준비한다. 시트 이름은 `BeyondPack`을 쓴다(기존 `BeyondPack_Master`도 호환, 둘 다 없으면 첫 시트).
2. `설정·관리자 도구 > Excel 비상 업데이트`에서 파일을 고른다.
3. 안내창에서 계속을 누른다.
4. 상품 건수와 상태를 확인한다.

Excel을 적용해도 Google Sheet 주소와 다음 실행 시 자동 업데이트는 유지된다.

## 10. Google Sheet 관리 기준

### 10.1 열

`BeyondPack` 탭 첫 행에 다음 이름을 쓴다.

```text
FNSKU,ItemCode,SKU,CountryCode,ProductName,ProductNameEn,AmazonAccount,Status,SourceModifiedAt,DataVersion,SchemaVersion
```

- 필수값: `FNSKU`, `ItemCode`, `SKU`, `CountryCode`, `ProductName`
- 화면의 국가는 `CountryCode`를 쓴다. 기존 파일의 `CountryName`은 있어도 읽지만 새로 만들지 않는다.
- `SchemaVersion`은 `2`를 쓴다.
- 활성 상품의 `Status`는 `Published`, `Active`, `Y` 중 하나다. **비워 두면 사용중지로 처리되어 조회되지 않는다.**

### 10.2 국가별 등록

FNSKU가 같아도 국가가 다르면 국가별로 한 행씩 만든다.

```text
FNSKU       CountryCode
X001ABC123  US
X001ABC123  CA
X001ABC123  JP
```

같은 `FNSKU + CountryCode` 조합은 중복 등록할 수 없다. 프로그램의 조회키다.

### 10.3 반영 절차

1. Sheet를 수정한다.
2. 필수값과 중복 여부를 검토한다.
3. `SourceModifiedAt`, `DataVersion`을 갱신한다. `DataVersion`이 비면 프로그램이 내용 기반 버전을 자동 생성한다.
4. 포장 PC에서 `F2`를 누른다.
5. 상품 건수와 대표 변경 상품을 조회해 확인한다.

전체 상품 수가 기존보다 **20% 이상 줄거나** 필수 열·필수값·중복·스키마에 문제가 있으면 업데이트가 차단되고 기존 DB가 유지된다.

## 12. 데이터 위치와 복구

### 12.1 이 PC에 저장되는 것

```text
%LOCALAPPDATA%\BeyondPack\config.json                    설정
%LOCALAPPDATA%\BeyondPack\data\products.current.json     활성 상품DB 포인터
%LOCALAPPDATA%\BeyondPack\data\products.snapshot.*.db    상품DB(현재·직전)
%LOCALAPPDATA%\BeyondPack\data\packaging.db              포장 실적·출고건·임시저장
%LOCALAPPDATA%\BeyondPack\logs\startup.log               시작 기록
```

프로그램 업데이트·제거에도 위 데이터는 유지된다. 다만 **디스크 고장은 보호하지 않는다.** 그래서 자동 백업을 설정한다.

설정 방법은 2.4를 참고한다.

### 12.2 백업 위치에 저장되는 것

백업 위치 아래 **이 PC 이름의 폴더**가 생긴다. 여러 작업대가 같은 위치를 써도 서로 덮어쓰지 않는다.

```text
<백업 위치>\<PC이름>\packaging.db              포장기록 전체 사본
<백업 위치>\<PC이름>\packing-YYYYMMDD.csv      그날 확정한 박스 실적
<백업 위치>\products\products-날짜-버전.xlsx   상품 마스터 사본
```

- **`packaging.db`** — PC를 교체하거나 고장났을 때 이 파일로 복구한다. 새 PC의 `%LOCALAPPDATA%\BeyondPack\data\`에 같은 이름으로 넣으면 출고건·박스번호·현황이 그대로 살아난다.
- **`packing-YYYYMMDD.csv`** — Excel로 바로 열린다. 여러 작업대의 파일을 모아 일자별 실적을 집계할 수 있다.
- **`products\products-날짜-버전.xlsx`** — 그때 쓰던 상품 마스터 전체다. Google Sheet가 지워지거나 잘못 편집돼도 이 파일을 `Excel 비상 업데이트`로 그대로 되돌릴 수 있다. **상품 내용이 바뀔 때만** 새 파일이 생기므로 시트를 고친 이력이 그대로 남는다. 파일 이름의 버전은 `DataVersion`이다.

`products` 폴더는 PC별로 나뉘지 않는다. 상품 마스터는 모든 작업대가 같은 내용을 쓰므로 한 벌만 쌓인다.

### 12.3 백업이 실행되는 시점

- 박스를 확정하고 20초 뒤(연속 확정 시 마지막 한 번만)
- 설정한 주기마다
- 프로그램을 정상 종료할 때
- `설정·관리자 도구 > 지금 백업`

**백업이 실패해도 포장 작업은 멈추지 않는다.** 배너에 `백업 실패`만 표시되고 다음 주기에 다시 시도한다. 공유 폴더가 하루 종일 끊겨 있었다면 복구된 뒤 한 번만 백업되면 그동안의 실적이 모두 포함된다(사본은 항상 전체를 다시 쓴다).

### 12.4 PC를 교체하거나 고장났을 때 복구

1. 새 PC에 **같은 버전**의 BeyondPack을 설치하고 한 번 실행한 뒤 종료한다.
2. 백업 위치의 `<PC이름>\packaging.db`를 새 PC의 `%LOCALAPPDATA%\BeyondPack\data\packaging.db`로 덮어쓴다.
3. 실행해서 해당 출고건을 입력하고 `4. 출고건 작업 현황`에 지난 박스가 보이는지, `다음 #N`이 이어지는지 확인한다.
4. `자동 백업 설정`에서 백업 위치를 다시 지정한다. PC 이름이 바뀌었다면 백업 폴더도 새 이름으로 생긴다.

상품DB는 복구할 필요가 없다. 실행하면 Google Sheet에서 다시 내려받는다.

### 12.5 Google Sheet를 잃었을 때 복구

시트가 지워졌거나 누가 잘못 편집해 되돌릴 수 없을 때다.

1. 먼저 **구글 드라이브 버전 기록**(시트 > 파일 > 버전 기록)으로 되돌려 본다. 이게 가능하면 여기서 끝난다.
2. 안 되면 백업 위치의 `products` 폴더를 열고 **되돌릴 시점의 파일**을 고른다. 이름의 날짜가 그 내용이 적용된 날이다.
3. `설정·관리자 도구 > Excel 비상 업데이트`에서 그 파일을 선택한다. Google Sheet와 같은 검증을 거쳐 반영된다.
4. 화면의 상품 건수와 국가 목록이 맞는지 확인한다.
5. 시트를 다시 만든다. 2번에서 고른 파일을 그대로 열어 `BeyondPack` 탭에 붙여넣으면 열 이름까지 맞는다.

> 시트를 복구하기 전까지는 `F2` 업데이트를 누르지 않는다. 비어 있거나 잘못된 시트를 다시 내려받으면 방금 되돌린 상품DB가 덮인다. (상품 수가 20% 이상 줄면 프로그램이 막지만, 그보다 작은 손실은 통과한다.)

### 12.6 진단파일

`설정·관리자 도구 > 관리자 진단파일 생성`은 바탕화면에 진단 ZIP을 만든다. 상품 원문과 포장 원문은 포함하지 않는다.

## 14. 작업 시작 전 점검

- [ ] 상태 배너가 `최신` 또는 `캐시 사용 중`인가
- [ ] 배너 오른쪽 백업 표시가 빨강이 아닌가
- [ ] 작업 국가·작업자·출고건이 채워져 있는가
- [ ] `다음 #N`이 이어작업 기준으로 맞는가
