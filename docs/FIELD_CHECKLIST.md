# BeyondPack 현장 도입 점검표

설치 직후 **작업 PC 1대에서** 이 순서대로 확인한다. A~D를 통과해야 그 PC로 실작업을 시작하고, E까지 통과해야 나머지 PC로 확대한다.

인쇄해서 체크하며 진행하기를 권장한다. 하나라도 막히면 그 항목에서 멈추고 개발 담당자에게 **항목 번호와 화면의 오류코드(`BP-xxx-nnn`)** 를 전달한다.

| 점검일 | | 점검자 | | PC 이름 | |
|---|---|---|---|---|---|
| 프로그램 버전 | | 라벨 프린터 모델 | | 스캐너 모델 | |

## A. 설치와 기본 설정 (관리자, 20분)

| # | 확인 사항 | 통과 기준 | 결과 |
|---|---|---|---|
| A-1 | 설치파일 실행 | 관리자 권한 요구 없이 설치 완료, 바탕화면 아이콘 생성 | ☐ |
| A-2 | 프로그램 실행 | 창 제목이 `BeyondPack <버전> · BEYOND EARTH` | ☐ |
| A-3 | `Sheet 설정`에 Google Sheet 주소 등록 | 상태 배너가 `최신`, 상품 건수가 실제 등록 건수와 일치 | ☐ |
| A-4 | 작업 국가 목록 확인 | 실제 운영 중인 국가가 모두 보인다 | ☐ |
| A-5 | Windows 드라이버에 라벨 용지 등록 | `인쇄 기본 설정`에 `40 x 25mm`가 있다 | ☐ |
| A-6 | `설정·관리자 도구 > 라벨 설정` | 안내줄이 **초록**(`이 프린터에 40×25mm 용지가 등록되어 있습니다`) | ☐ |
| A-7 | `자동 백업 설정`에 공유 폴더 지정 | 배너 오른쪽이 **`백업 HH:MM`(초록)** | ☐ |
| A-8 | 백업 위치 확인 | `<백업 위치>\<PC이름>\`에 `packaging.db`와 당일 CSV 생성 | ☐ |

> A-6이 노란색이면 A-5가 덜 된 것이다. 여기서 넘어가면 라벨이 A4로 나가 잘린다.
> A-7이 `백업 미설정`이면 실적이 이 PC에만 남는다. 반드시 지정하고 넘어간다.

## B. 스캐너와 라벨 실물 시험 (30분)

| # | 확인 사항 | 통과 기준 | 결과 |
|---|---|---|---|
| B-1 | FNSKU 입력칸에 커서를 두고 실물 바코드 스캔 | 스캔 즉시 상품이 조회된다(Enter 별도 입력 불필요) | ☐ |
| B-2 | **한글 입력 상태(한/영 키를 한글로)에서 스캔** | 정상 조회된다. 깨진 문자가 들어가면 즉시 보고 | ☐ |
| B-3 | 화면 상품정보와 실물 대조 | 품목명·품목코드·SKU·국가가 실물과 일치 | ☐ |
| B-4 | `테스트 라벨 출력` | `#1`, `#2` 두 장이 **잘림 없이** 나오고 빈 라벨이 섞이지 않는다 | ☐ |
| B-5 | 라벨 글자 크기 확인 | 1m 거리에서 `#번호`가 읽힌다 | ☐ |
| B-5-1 | 라벨 요약 줄 확인 | 스캔한 **FNSKU**가 그대로 인쇄된다 | ☐ |
| B-6 | 라벨 접착 확인 | 실제 박스 표면에 붙였을 때 떨어지지 않는다 | ☐ |

> B-4에서 빈 라벨이 함께 나오면 라벨 크기 설정이 실제 롤과 다르다. 롤을 자로 재서 `라벨 설정`에 mm로 다시 넣는다.

## C. 박스번호 — 가장 중요한 항목 (30분)

박스번호가 틀리면 출고 후 어느 박스인지 식별할 수 없다. **전부 통과해야 한다.**

| # | 시나리오 | 통과 기준 | 결과 |
|---|---|---|---|
| C-1 | 출고건 `TEST-A` 입력 | 옆에 `다음 #1` 표시 | ☐ |
| C-2 | 박스수량 **3**으로 확정 | 라벨 `#1` `#2` `#3` **3장**이 순번대로 나온다 | ☐ |
| C-3 | 이어서 박스수량 2로 확정 | `#4` `#5` | ☐ |
| C-4 | **프로그램 종료 후 재실행**, `TEST-A` 입력 | `다음 #6`, 현황 탭에 이전 5박스가 그대로 보인다 | ☐ |
| C-5 | 그 상태로 박스수량 1 확정 | `#6` | ☐ |
| C-6 | 출고건을 `TEST-B`로 변경 | `다음 #1`, 현황이 비어 있다 | ☐ |
| C-7 | 다시 `TEST-A`로 변경 | `다음 #7`, 이전 6박스가 다시 보인다 | ☐ |
| C-8 | 출고건을 비우고 확정 시도 | `출고건 번호를 입력하세요`로 막힌다 | ☐ |
| C-9 | 박스수량을 비우고 확정 시도 | `박스수량은(는) 1 이상이어야 합니다`로 막힌다 | ☐ |
| C-10 | 출고건 몇 글자만 입력 | 최근 사용한 출고건이 목록으로 뜬다 | ☐ |
| C-11 | 현황 탭에서 **중간 행** 선택 | `선택 박스 수정`·`삭제`가 잠겨 있다 | ☐ |
| C-12 | **마지막 행** 선택 → `선택 박스 수정` → 무게 고쳐 재확정 | 같은 박스번호가 다시 붙는다 | ☐ |
| C-13 | 마지막 행 선택 → `선택 박스 삭제` | 목록에서 사라지고 `다음 #N`이 그 번호로 되돌아간다 | ☐ |
| C-14 | 수정·삭제 시 사유 입력창 | 사유를 비우면 진행되지 않는다 | ☐ |

## D. 백업과 복구 — 실적이 실제로 살아나는지 (30분)

백업은 **복구까지 해봐야** 확인된 것이다.

| # | 시나리오 | 통과 기준 | 결과 |
|---|---|---|---|
| D-1 | 박스 확정 후 20초 대기 | 배너의 백업 시각이 갱신된다 | ☐ |
| D-2 | 백업 폴더 확인 | `packaging.db`와 `packing-<오늘날짜>.csv`가 있다 | ☐ |
| D-3 | CSV를 Excel로 열기 | 한글이 깨지지 않고, 첫 열이 `출고건`, `박스확정시각` 열이 있다 | ☐ |
| D-4 | **네트워크 케이블을 뽑거나 공유 폴더 차단** 후 박스 확정 | 배너에 `백업 실패`만 뜨고 **포장 작업은 그대로 된다** | ☐ |
| D-5 | 연결 복구 후 `지금 백업` | 백업이 성공하고, 끊겨 있는 동안 확정한 박스도 CSV에 들어 있다 | ☐ |
| D-6 | **복구 시험** — 다른 PC(또는 다른 폴더)에 설치 후 백업 `packaging.db`를 데이터 폴더에 덮어쓰기 | `TEST-A` 입력 시 현황과 `다음 #7`이 그대로 살아난다 | ☐ |
| D-7 | 프로그램 정상 종료 | 종료가 지연되지 않고, 종료 후 백업 파일 시각이 갱신되어 있다 | ☐ |

> D-6 절차는 [사용자 매뉴얼 12.4](USER_MANUAL.md)를 따른다.

## 운영 규칙으로 정해야 할 것

점검과 별개로, 배포 전에 다음을 정하고 작업자에게 공지한다.

1. **출고건 문서번호 표기 규칙** — 하나로 통일한다. 표기가 갈리면 박스번호가 `#1`부터 다시 시작한다.
2. **한 출고건은 한 작업대에서 처리** — 박스번호와 작업 현황은 그 PC 안에서만 이어진다. 두 대가 나눠 작업하면 번호가 겹친다.
3. **프로그램은 정상 종료** — 종료할 때 마지막 백업이 실행된다.
4. **출고건 종료 시 `출고건 Excel 저장`** — 자동 백업과 별개로 정산·공유용 파일을 남긴다.
5. **`백업 실패` 표시를 보면 관리자에게 알린다** — 작업은 계속한다.

## 아직 지원하지 않는 것 (기대 조정용)

현장에 안내해 두어야 오해가 없다.

- **라벨에 바코드가 없다.** 박스 라벨은 사람이 읽는 번호만 인쇄된다. 박스를 스캔해서 대조하는 작업은 아직 할 수 없다.
- **여러 작업대가 같은 출고건을 나눠 작업할 수 없다.** 박스번호가 겹친다.
- **재고 수량을 관리하지 않는다.** 이 프로그램은 포장 기록 도구이며 입출고 재고 원장이 아니다.
- **확정한 박스는 마지막 것만 수정·삭제할 수 있다.** 중간 박스를 정정해야 하면 관리자에게 전달한다.
