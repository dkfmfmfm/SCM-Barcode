# BeyondPack 2.3.3

프로그램 안의 **사용 안내(F1)**와 현장 카드를 지금 기능에 맞춰 다시 정리했습니다.

기능 변경은 없습니다. 2.3.2를 쓰고 있다면 급히 올릴 필요는 없고, 다음 설치 때 함께 반영하면 됩니다.

## 사용 안내(F1)에 들어간 것

사용 안내는 `USER_MANUAL`을 그대로 읽어 `##` 단위로 나눠 보여 줍니다. 그래서 설명서를 고치면 프로그램 안의 안내도 같이 바뀝니다.

### 새 항목 — 숫자를 입력할 때

2.3.2에서 숫자칸 동작이 바뀌었는데 설명이 없었습니다. `02. 화면과 입력 요령`에 넣었습니다.

| 하려는 것 | 하는 법 |
|---|---|
| 값을 새로 넣기 | 칸을 **한 번** 누르고 숫자를 칩니다 |
| 자릿수 하나만 고치기 | 칸을 **한 번 더** 눌러 커서를 두고 고칩니다 |
| 1씩 올리고 내리기 | 오른쪽 **▲ / ▼** |

**숫자를 쳤는데 칸이 비어 보이면 관리자에게 알린다**는 문장도 함께 넣었습니다. 2.3.2 이전 버전이 남아 있는 PC를 찾아내기 위한 것입니다.

### 고친 것

- **정정과 취소의 라벨 처리를 구분했습니다.** 이전에는 둘 다 "기존 라벨을 폐기"라고 적혀 있었는데, 정정은 박스번호가 그대로라 **덮어 붙이는** 것이 맞습니다.

  | | 박스번호 | 라벨 |
  |---|---|---|
  | 정정 | 그대로 | 같은 번호로 다시 뽑아 덮어 붙임 |
  | 확정 취소 | 사라짐 | 폐기 |
  | 중간 박스 취소·수량 변경 | 뒤 번호가 당겨짐 | 밀린 박스를 모두 다시 붙임 |

- `화면 읽기` 표에 **재부착 안내(주황)** 줄을 넣었습니다. 탭 위에 뜨는 안내입니다.
- 제목에서 버전을 뺐습니다. 창 제목표시줄이 이미 실행 중인 버전을 보여 주므로, 설명서에 박아 두면 릴리즈마다 손대야 하고 잊으면 틀린 값이 남습니다.

## 현장 빠른 안내(`OPERATOR_GUIDE`) 다시 씀

한 장짜리 카드가 2.3.0 기준이라 여러 곳이 사실과 달랐습니다.

| 항목 | 이전 | 지금 |
|---|---|---|
| 정정 대상 | "마지막 박스를 선택합니다" | **어느 박스든** (어제 것도) |
| 정정 후 라벨 | "기존 라벨은 폐기합니다" | 같은 번호로 **덮어 붙입니다** |
| 숫자 입력 | 설명 없음 | 맨 앞에 넣음 |
| 항공·해상 | 설명 없음 | 출고건만 바꾸면 됨 |
| 번호 밀림·재부착 | 설명 없음 | 절차와 중단 기준 |
| 작업 국가 | 설명 없음 | 처음부터 미국 |

**상자가 아직 손에 닿을 때만 진행한다**, **이미 실었으면 관리자에게 알린다**를 눈에 띄게 적었습니다.

## 릴리즈 빌드가 서로를 취소하던 문제

`release-windows` 워크플로가 **PR 검증 빌드와 main 배포 빌드를 같은 동시성 그룹**에 두고 `cancel-in-progress: true`를 걸고 있었습니다. PR을 하나 올리면 진행 중이던 배포 빌드가 취소됩니다.

실제로 **v2.3.2 배포 빌드가 이렇게 취소되어 릴리즈 파일이 만들어지지 않았습니다.** 머지는 됐는데 설치파일이 없는 상태였습니다.

이벤트와 ref로 그룹을 나누고, 취소는 PR 빌드에서만 하도록 바꿨습니다.

```yaml
group: beyondpack-windows-release-${{ github.event_name }}-${{ github.ref }}
cancel-in-progress: ${{ github.event_name == 'pull_request' }}
```

이제 PR을 여러 번 올려도 배포 빌드는 끝까지 돕니다.

## 설치 방법

1. 작업관리자에서 실행 중인 `BeyondPack.exe`를 모두 종료합니다.
2. `BeyondPack-2.3.3-Windows-x64-Setup.exe`로 기존 버전 위에 설치합니다.
3. **F1**을 눌러 `02. 화면과 입력 요령`에 `숫자를 입력할 때`가 있는지 확인합니다.

설치본에는 `BeyondPack-2.3.3-User-Guide.html`도 함께 들어갑니다. 인터넷 없이 열리므로 인쇄해서 작업대에 둘 수 있습니다.

기존 상품DB, 포장기록, 출고건 기록, 라벨·백업 설정은 모두 유지됩니다.
