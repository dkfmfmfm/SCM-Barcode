# BeyondPack 2.2.8

## 포장 실적 자동 백업

포장 실적은 그동안 작업 PC의 `packaging.db`에만 있었다. 디스크가 고장나거나 PC를 교체하면 Excel로 미리 빼두지 않은 실적은 복구할 수 없었다.

이제 지정한 위치에 **자동으로 사본을 남긴다.**

### 설정 (PC마다 한 번)

`설정·관리자 도구 > 자동 백업 설정`

| 항목 | 기본값 | 설명 |
|---|---|---|
| 백업 위치 | 없음 | 공유 드라이브(`\\서버\물류\BeyondPack`)나 동기화 폴더 |
| 백업 주기 | 10분 | |
| CSV 보관 | 90일 | 일자별 CSV만 정리한다. DB 사본은 지우지 않는다 |

### 저장되는 파일

```text
<백업 위치>\<PC이름>\packaging.db              포장기록 전체 사본
<백업 위치>\<PC이름>\packing-YYYYMMDD.csv      그날 확정한 박스 실적
```

- **PC 이름으로 폴더가 갈린다.** 여러 작업대가 같은 위치를 써도 서로 덮어쓰지 않는다. 한글 PC 이름도 그대로 쓴다.
- `packaging.db`는 SQLite 백업 API로 만든 **일관된 사본**이다. 작업 중에 복사해도 중간 상태가 섞이지 않는다. 이 파일 하나로 출고건·박스번호·작업 현황이 그대로 복구된다.
- CSV는 Excel에서 바로 열린다(BOM 포함). 여러 작업대의 파일을 모아 일자별 실적을 집계할 수 있다.

### 언제 실행되나

- 박스 확정 20초 뒤 — 연속으로 확정해도 마지막 한 번만 실행한다
- 설정한 주기마다
- 프로그램 정상 종료 시
- `설정·관리자 도구 > 지금 백업`

**백업은 포장 작업을 막지 않는다.** 별도 스레드에서 실행되며, 공유 폴더가 끊겨 있으면 배너에 `백업 실패`만 표시하고 다음 주기에 다시 시도한다. 사본은 항상 전체를 다시 쓰므로, 하루 종일 끊겼다가 복구되어도 한 번만 성공하면 그동안의 실적이 모두 포함된다.

### 화면 표시

상품DB 상태 배너 오른쪽에 백업 상태가 붙는다.

| 표시 | 뜻 |
|---|---|
| `백업 02:41`(초록) | 그 시각에 사본이 저장됐다 |
| `백업 실패`(빨강) | 백업 위치에 쓰지 못했다. 마우스를 올리면 이유가 나온다 |
| `백업 대기`(회색) | 설정은 됐고 아직 이번 실행에서 백업하지 않았다 |
| `백업 미설정`(빨강) | **실적이 이 PC에만 있다.** 관리자가 위치를 지정해야 한다 |

### 복구 절차

1. 새 PC에 같은 버전을 설치하고 한 번 실행한 뒤 종료한다.
2. 백업 위치의 `<PC이름>\packaging.db`를 새 PC의 `%LOCALAPPDATA%\BeyondPack\data\packaging.db`로 덮어쓴다.
3. 해당 출고건을 입력해 `4. 출고건 작업 현황`과 `다음 #N`이 살아났는지 확인한다.

## 함께 수정한 것

- **박스 확정 후 정상 종료했는데도 다음 실행에서 `미완료 작업 복구` 창이 뜨던 문제 수정.** 2.2.7에서 출고건을 임시저장 대상에 넣으면서, 확정 후 출고건만 남은 빈 초안이 저장되고 있었다. 이제 구성품이나 포장정보가 실제로 있을 때만 임시저장한다.
- 포장실적 Excel과 백업 CSV에 **`박스확정시각`** 열을 추가했다. 기존 `작업일시`는 작업을 시작한 시각이라, 며칠에 걸친 출고건에서 각 박스를 언제 포장했는지 알 수 없었다.

## 설치 방법

1. 작업관리자에서 실행 중인 `BeyondPack.exe`를 모두 종료한다.
2. `BeyondPack-2.2.8-Windows-x64-Setup.exe`를 실행해 기존 버전 위에 설치한다.
3. 창 제목이 `BeyondPack 2.2.8 · BEYOND EARTH`인지 확인한다.
4. **`설정·관리자 도구 > 자동 백업 설정`에서 백업 위치를 지정한다.**
5. 배너 오른쪽이 `백업 HH:MM`(초록)으로 바뀌는지 확인한다.
6. 백업 위치에 `<PC이름>` 폴더와 `packaging.db`, 당일 CSV가 생겼는지 확인한다.

기존 상품DB, 포장기록, 출고건 기록, 라벨 설정은 모두 유지된다. 기존 `config.json`에 백업 설정이 없어도 그대로 읽힌다.

## 남은 사항

박스번호와 작업 현황은 여전히 **작업 PC 안에서만** 이어진다. 백업은 실적 소실을 막을 뿐, 같은 출고건을 두 작업대가 나눠 작업하는 문제는 해결하지 않는다. 중앙 발번·수집 서비스가 필요하며 [`docs/REVIEW_2.2.3.md`](REVIEW_2.2.3.md) P2-3에 정리되어 있다.
